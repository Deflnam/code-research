# Code Research: Исследование помехоустойчивого кодирования

Кроссплатформенное десктопное приложение на языке Go с графическим интерфейсом для исследования свойств помехоустойчивого кодирования в режиме обнаружения ошибок. Приложение моделирует передачу данных по зашумленному каналу и собирает статистические метрики надежности выбранного кода.

## 🚀 Как запускать программу

Для работы приложения требуется установленный компилятор **Go** (рекомендуется версия 1.21+). Так как графический интерфейс базируется на библиотеке Fyne, требуются базовые инструменты сборки (CGO). На macOS они обычно доступны «из коробки» (Command Line Tools), на Linux может потребоваться пакет `gcc` и библиотеки X11/Wayland.

1. Склонируйте репозиторий (или перейдите в папку с исходным кодом):
   ```bash
   git clone [https://github.com/Deflnam/code-research.git](https://github.com/Deflnam/code-research.git)
   cd code-research


2. Установите зависимости:
   go mod tidy

3. Запустите приложение:
   go run cmd/app/main.go


 Как работает программа

Процесс симуляции происходит в оперативной памяти в виде высокоскоростного цикла. Для каждого передаваемого пакета выполняются следующие шаги:

1. Генерация сообщения: Формируется случайная последовательность байт (информационный блок) заданной длины.
2. Кодирование: Вычисляется контрольная сумма (избыточные проверочные биты), которая прикрепляется к исходному блоку.
3. Канал связи: Пакет проходит через модель канала с шумом. В зависимости от заданной вероятности P, биты могут быть инвертированы.
4. Декодирование (обнаружение): На приемной стороне проверочные биты отсекаются, контрольная сумма пересчитывается и сравнивается с принятой.
5. Сбор статистики: Оценивается результат передачи (успех, обнаруженная ошибка или ложный прием).

Цикл автоматически останавливается при достижении лимита переданных блоков или при накоплении заданного числа зафиксированных ошибок (для обеспечения достаточного доверительного интервала).

 Используемые алгоритмы

⚬ CRC-32 (Cyclic Redundancy Check): Алгоритм циклического избыточного кода (стандарт IEEE). Обладает высокой обнаруживающей способностью. Добавляет 4 байта избыточности. Если искажения в канале связи приводят к коллизии (искаженный пакет дает ту же контрольную сумму), возникает эффект «ложного приема».
⚬ БСК (Дискретный двоичный симметричный канал): Математическая модель канала. Симметричность означает, что вероятность искажения 1 в 0 равна вероятности искажения 0 в 1. Реализована программно через побитовый проход и операцию инвертирования (XOR) с учетом случайной вероятности ошибки P.

 Что подсчитывает программа

⚬ Передано блоков: Общее количество сгенерированных и отправленных пакетов.
⚬ Корректно принято: Пакеты, прошедшие через канал без единого искаженного бита.
⚬ Обнаружено ошибок: Пакеты, в которых возникли искажения, успешно выявленные декодером (несовпадение CRC).
⚬ Пропущено ошибок (Ложный прием): Критическая ситуация (коллизия), когда биты были искажены, но итоговая контрольная сумма совпала с ожидаемой. Алгоритм ошибочно принимает искаженный пакет за верный.

 Экспорт данных

Результаты экспериментов можно выгрузить, нажав «Сохранить как (CSV)...». Вы можете выбрать папку (например, Рабочий стол) и сохранить файл.

Формат CSV (Comma-Separated Values) позволяет легко импортировать результаты в Excel, Numbers или Google Таблицы для построения графиков и анализа зависимостей (например, вероятности ложного приема от уровня шума).

 Структура проекта

⚬ cmd/app/main.go — графический интерфейс (GUI), инициализация окна, сбор параметров и экспорт.
⚬ internal/channel/bsc.go — математическая модель БСК (внесение шума).
⚬ internal/coder/crc.go — логика кодирования и обнаружения ошибок (CRC-32).
⚬ internal/simulation/run.go — главный цикл симуляции и сбор статистики.
